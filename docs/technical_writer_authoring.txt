ИНСТРУКЦИЯ ДЛЯ ТЕХНИЧЕСКОГО ПИСАТЕЛЯ
Авторинг страниц "Справка" и "Быстрый старт" через markdown

1) ОБЩИЙ СЦЕНАРИЙ РАБОТЫ
1. Откройте страницу в режиме авторинга:
   - Справка: /help?authoring=1
   - Быстрый старт: /quick-start?authoring=1
2. Нажмите "Экспорт md" и сохраните текущий файл.
3. Внесите правки локально в редакторе.
4. Вернитесь в сайт и нажмите "Импорт md".
5. Если есть ошибки контракта, сайт покажет список ошибок и не применит файл.
6. Если ошибок нет, изменения применятся в текущей сессии браузера.
7. При необходимости нажмите "Сбросить к дефолту", чтобы вернуться к встроенной версии.

Важно:
- Импортированная версия хранится только в текущей сессии браузера.
- На сервер изменения не отправляются.
- Финальную согласованную версию файла передайте разработчику для выкладки.

2) КОНТРАКТ ДЛЯ СТРАНИЦЫ "СПРАВКА"
Файл: help.md

2.1. Правило табов
- Каждый заголовок первого уровня (H1) создает отдельный таб.
- H1 ОБЯЗАН иметь явный id:
  Формат: # Название таба {#tab-id}

Пример:
# Документооборот {#documents}

2.2. Требования к id у H1
- id обязателен для каждого H1.
- id должен быть уникальным в файле.
- Допустимый формат id:
  - только латиница в нижнем регистре, цифры и дефис
  - начинается с буквы или цифры
  - регулярное правило: [a-z0-9][a-z0-9-]*

2.3. Контент внутри таба
- После H1 можно использовать обычный markdown:
  - H2/H3/H4
  - списки
  - таблицы
  - ссылки
  - цитаты
- У каждого таба должен быть контент (пустые табы считаются ошибкой).

2.4. Ссылки и якоря
- Ссылка на конкретный таб:
  /help?tab=documents
- Ссылка на конкретный якорь внутри таба:
  /help?tab=documents#anchor-id
- Для локальных якорей используйте id в заголовках (через {#...}) там, где нужно стабильное имя.

2.5. Частые ошибки
- "Заголовок H1 должен содержать явный id..."
  Причина: написан H1 без {#id}.
- "Дублирующийся id секции ..."
  Причина: два H1 с одинаковым id.
- "Секция ... не содержит контента."
  Причина: есть H1, но после него нет содержимого.

3) КОНТРАКТ ДЛЯ СТРАНИЦЫ "БЫСТРЫЙ СТАРТ"
Файл: quickstart.md

3.1. Общая структура сценария
- Каждый H1 = отдельный сценарий (карточка/шаг).
- H1 также обязан иметь явный id:
  Формат: # Заголовок сценария {#scenario-id}

Минимальная структура одного сценария:
# Название шага {#step-id}
> Краткое вводное описание шага

## Шаги
- Пункт 1
- Пункт 2

## Понятия
- [Название понятия](/help?tab=...#...)

## CTA
[Текст кнопки](/target-link)

3.2. Блоки и их назначение
- Блок "> ..." (цитата) = вводный текст карточки (intro).
- "## Шаги" = список основных пунктов шага (обязателен).
- "## Понятия" = список ссылок на важные понятия (необязателен, но желателен).
- "## CTA" = кнопка перехода (необязательна).

3.3. Формат ссылок в "Понятия"
- Строго markdown-список со ссылками:
  - [Текст](/help?tab=orders#order_struct_desc)

3.4. Частые ошибки
- "Сценарий ... не содержит блока '## Шаги'."
  Причина: отсутствует обязательный раздел с пунктами.
- "Сценарий ... не содержит краткого описания (blockquote '> ...')."
  Причина: нет строки с вводным описанием в формате цитаты.
- Ошибки H1/id такие же, как в разделе "Справка".

4) РЕКОМЕНДАЦИИ ПО АВТОРИНГУ
- Не меняйте id без необходимости: это ломает внешние ссылки.
- Если меняете заголовок, старайтесь сохранить старый id.
- Делайте короткие, стабильные id (например: documents, supply, order-cancel).
- Перед передачей финального файла разработчику проверьте:
  1) импорт проходит без ошибок;
  2) открываются нужные табы;
  3) работают ссылки на якоря.

5) КРАТКИЙ ЧЕК-ЛИСТ ПЕРЕД СДАЧЕЙ
- Файл импортируется без ошибок.
- Нет дублирующихся id у H1.
- У каждого H1 есть {#id}.
- Для Quick Start у каждого сценария есть:
  - intro в виде строки с ">"
  - раздел "## Шаги" с пунктами
- Критичные ссылки (/help?tab=...#...) открываются корректно.
