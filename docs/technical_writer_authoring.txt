ИНСТРУКЦИЯ ДЛЯ ТЕХНИЧЕСКОГО ПИСАТЕЛЯ
Авторинг контента: основная справка, быстрый старт, инлайн-справки (markdown)

1) ОБЩИЙ СЦЕНАРИЙ РАБОТЫ
1. Откройте раздел «Авторинг»: /authoring (пункт «Авторинг» в левом меню).
2. Для нужного файла нажмите «Скачать» и сохраните текущую версию (.md).
3. Внесите правки локально в редакторе.
4. Нажмите «Загрузить» и выберите исправленный файл.
5. Если есть ошибки контракта, портал покажет список ошибок и не применит файл.
6. Если ошибок нет, изменения сохраняются в браузере (localStorage).
7. При необходимости «Сбросить к дефолту» вернёт встроенную версию из репозитория.

Файлы на странице Авторинг:
- help.md — основная справка (табы).
- page-help.md — инлайн-справки под заголовками страниц и табов/вариантов.
- quickstart.md — быстрый старт (сценарии-карточки).

Режим техписателя для инлайн-справок (Writer mode):
- На странице /authoring включите флажок «Writer mode для page-help».
- В этом режиме на всех страницах с инлайн-справкой всегда видны иконка и панель; пустые места показывают шаблон заголовка и кнопку «Скопировать» для вставки в page-help.md.

Важно:
- Импортированные версии хранятся только в браузере пользователя, на сервер не отправляются.
- Финальную согласованную версию каждого файла передайте разработчику для включения в репозиторий и выкладки.

2) КОНТРАКТ ДЛЯ СТРАНИЦЫ "СПРАВКА"
Файл: help.md

2.1. Правило табов
- Каждый заголовок первого уровня (H1) создает отдельный таб.
- H1 ОБЯЗАН иметь явный id:
  Формат: # Название таба {#tab-id}

Пример:
# Документооборот {#documents}

2.2. Требования к id у H1
- id обязателен для каждого H1.
- id должен быть уникальным в файле.
- Допустимый формат id:
  - только латиница в нижнем регистре, цифры и дефис
  - начинается с буквы или цифры
  - регулярное правило: [a-z0-9][a-z0-9-]*

2.3. Контент внутри таба
- После H1 можно использовать обычный markdown:
  - H2/H3/H4
  - списки
  - таблицы
  - ссылки
  - цитаты
- У каждого таба должен быть контент (пустые табы считаются ошибкой).

2.4. Ссылки и якоря
- Ссылка на конкретный таб:
  /help?tab=documents
- Ссылка на конкретный якорь внутри таба:
  /help?tab=documents#anchor-id
- Для локальных якорей используйте id в заголовках (через {#...}) там, где нужно стабильное имя.

2.5. Частые ошибки
- "Заголовок H1 должен содержать явный id..."
  Причина: написан H1 без {#id}.
- "Дублирующийся id секции ..."
  Причина: два H1 с одинаковым id.
- "Секция ... не содержит контента."
  Причина: есть H1, но после него нет содержимого.

3) КОНТРАКТ ДЛЯ СТРАНИЦЫ "БЫСТРЫЙ СТАРТ"
Файл: quickstart.md

3.1. Два уровня: сценарии и карточки
- **H1** — сценарий использования. Отображается как **таб** на странице (если сценариев несколько). Обязателен явный id:
  Формат: # Название сценария {#scenario-id}
  Правила id такие же, как у H1 в справке: [a-z0-9][a-z0-9-]*, уникальность в файле.
- После H1 допускается **преамбула** (markdown до первой карточки), например вводная цитата:
  > Текст подзаголовка страницы «Быстрый старт» берётся из первой такой цитаты **первого** сценария.

- **H2** — карточка внутри сценария. Обязателен явный блок атрибутов в одной строке:
  Формат: ## Заголовок карточки {#card-id type=long|short [step=N] [icon=ключ]}

  Внутри {...} через пробел:
  - первый токен всегда **#card-id** (id карточки, уникален в пределах всего файла — нужно для инлайн-справки tab:quick-start:<card-id>);
  - **type=long** — в сетке показываются заголовок, тизер из цитат и «Подробнее»; полный текст — на отдельном экране;
  - **type=short** — весь markdown карточки показывается сразу в ячейке сетки;
  - **step=N** (необязательно) — если указан, в карточке показывается подпись «Шаг N»; без атрибута `step` бейдж не выводится;
  - **icon=ключ** (необязательно) — если указан и ключ есть в реестре портала, показывается иконка; без атрибута `icon` или при неизвестном ключе иконка не выводится (Font Awesome в md не используется).

3.2. Контент карточки (markdown под H2)
- Между заголовком H2 текущей карточки и следующим H2 — **сырое тело** карточки: списки, абзацы, заголовки H3/H4, ссылки и т.д. Рендерится через markdown.
- Для **type=long** сразу после H2 должна идти хотя бы одна строка цитаты **> ...** (тизер для сетки). Остальное тело — произвольный markdown (в т.ч. дальнейшие цитаты, списки).

3.3. Стили ссылок «как Понятия и CTA» (без отдельных секций ## Шаги / ## Понятия / ## CTA)
Используйте remark-attrs у ссылки в одной строке:
- стиль «понятие» (чип): [Текст](/help?tab=...#...){.qs-concept}
- стиль «кнопка действия»: [Текст кнопки](/path){.qs-cta}

Пример блока полезных ссылок:

**Полезные ссылки**

- [Статья в справке](/help?tab=goods#good_id_desc){.qs-concept}

[Перейти в раздел](/goods){.qs-cta}

3.4. URL и инлайн-справка
- Сценарий: /quick-start?tab=<scenario-id>
- Длинная карточка открыта: добавьте &card=<card-id>
- В page-help.md секции ### для шагов используют id **карточки**: {#tab:quick-start:<card-id>}.

3.5. Частые ошибки
- «Сценарий не содержит карточек» — нет ни одной строки H2 с форматом {#...}.
- «Карточка (type=long): сразу после заголовка нужна цитата» — нет строки > в начале тела.
- «Дублирующийся id карточки» — два H2 с одинаковым #card-id в файле.
- Ошибки H1 такие же, как в разделе «Справка» (пустой сценарий, дубли id, нет {#id}).

4) РЕКОМЕНДАЦИИ ПО АВТОРИНГУ
- Не меняйте id без необходимости: это ломает внешние ссылки.
- Если меняете заголовок, старайтесь сохранить старый id.
- Делайте короткие, стабильные id (например: documents, supply, order-cancel).
- Перед передачей финального файла разработчику проверьте:
  1) импорт на /authoring проходит без ошибок;
  2) открываются нужные табы сценариев и карточки;
  3) работают ссылки на якоря.

5) КРАТКИЙ ЧЕК-ЛИСТ ПЕРЕД СДАЧЕЙ
- Каждый изменённый файл импортируется на /authoring без ошибок.
- help.md: нет дублирующихся id у H1; у каждого H1 есть {#id}.
- quickstart.md: у каждого сценария (H1) есть хотя бы одна карточка H2 с {#card-id type=...}; id карточек уникальны в файле; у type=long после H2 есть цитата ">"; ссылки-чипы и CTA помечены {.qs-concept} и {.qs-cta} где нужно.
- page-help.md: уникальные метки; секции ## с телом текста (пустые секции — ошибка контракта).
- Критичные ссылки (/help?tab=...#...) открываются корректно.

6) ИНЛАЙН-СПРАВКИ ДЛЯ СТРАНИЦ И ТАБОВ
Файл: page-help.md

6.1. Назначение
- Файл задаёт краткие пояснения под заголовком страницы или для таба/варианта интерфейса.
- Если секция по метке найдена и в ней есть текст — показывается иконка и раскрываемая панель.
- Если секции нет — при обычном режиме инлайн-блок не показывается; в Writer mode видна панель-заглушка с шаблоном заголовка для копирования.

6.2. Формат секций уровня страницы
- Заголовок H2 с id вида:
  ## Название {#page:<page-key>}

Примеры:
- ## Дашборд {#page:dashboard}
- ## Быстрый старт {#page:quick-start}
- ## Справка {#page:help}
- ## Входящие документы {#page:indocs}
- ## Карточка входящего документа {#page:indoc-detail}
- ## Исходящие документы {#page:outdocs}
- ## Карточка исходящего документа {#page:outdoc-detail}
- ## Товары {#page:goods}
- ## Карточка товара {#page:good-detail}
- ## Заказы {#page:orders}
- ## Карточка заказа {#page:order-detail}

6.3. Формат секций уровня таба/варианта
- Заголовок H3 с id вида:
  ### Название {#tab:<page-key>:<tab-key>}

Примеры:
- ### Операционный вид {#tab:dashboard:v1}
- ### Шаг: товары {#tab:quick-start:goods}
- ### Табы справки: заказы {#tab:help:orders}

6.4. Требования к меткам
- Метки должны быть уникальны в файле.
- Допустимые символы в ключах: латиница нижнего регистра, цифры, дефис, подчёркивание (в tab-key часто совпадает с id вкладки в коде, например supply_goods).
- Форматы:
  - страница: page:<page-key>
  - таб/вариант: tab:<page-key>:<tab-key>

6.5. Как узнать нужную метку и шаблон заголовка
- Включите Writer mode на /authoring и откройте нужную страницу или таб.
- В открытой янтарной панели внизу показаны строка «Шаблон заголовка» (полная строка ## или ### с {#...}) и кнопка «Скопировать» — вставьте в page-help.md без ручного набора.

6.6. Где уже подключено автосопоставление (этап 1)
- Страницы (page:*):
  - page:dashboard
  - page:quick-start
  - page:help
  - page:indocs
  - page:indoc-detail
  - page:outdocs
  - page:outdoc-detail
  - page:goods
  - page:good-detail
  - page:orders
  - page:order-detail
- Табы/варианты (tab:*):
  - tab:dashboard:v1
  - tab:help:<id активного таба справки>
  - tab:quick-start:<id карточки> (длинная карточка открыта на /quick-start?card=<id>; короткие карточки без отдельного экрана — при необходимости откройте сценарий с этой карточкой для подсказки)
  - tab:indocs:create-goods-supply (форма «Задание на оприходование» на странице входящих документов)
  - tab:indocs:create-goods-shipment (форма «Задание на отгрузку товаров»)
  - tab:indocs:create-orders-shipment (форма «Задание на отгрузку заказов»)
  - tab:indoc-detail:goods | orders | boxes | attrs | outdocs | files | photos | json (вкладки карточки входящего документа /indocs/:id)
  - tab:outdoc-detail:supply_goods | supply_expiry | shipment_pallets | correction_goods | shipments | outdoc_orders | return_orders | goods | sn | attrs | files | photos | json (вкладки карточки исходящего /outdocs/:id)
  - tab:goods:upload-goods (форма «Загрузка номенклатуры» на странице товаров)
  - tab:good-detail:info | movements | orders | eans | photos | sn (вкладки карточки товара /goods/:id)
  - tab:order-detail:goods | outdocs | events | shipment | photos | json (вкладки карточки заказа /orders/:id)

6.7. Минимальный шаблон секции
## Пример страницы {#page:example-page}
Короткое описание сценария, бизнес-контекст и ссылка в полную справку.

### Пример таба {#tab:example-page:example-tab}
Короткое пояснение по особенностям интерфейса и применимости фильтров.
